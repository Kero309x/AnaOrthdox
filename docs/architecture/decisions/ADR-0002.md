# ADR-0002: Adoption of Next.js 16 Active LTS and React 19 for Frontend Client

**Status:** SUPERSEDED & UPDATED (from Next.js 15 baseline to Next.js 16 Active LTS)  
**Date:** 2026-11-17  
**Deciders:** Principal Software Architect, Frontend Agent

---

## 1. Context and Problem Statement

Ana Orthodox serves heavy text and media canonical content that requires excellent search engine indexing (SEO for Arabic Coptic texts, Fathers' writings, liturgical calendar), instant first-contentful-paint (FCP) on mobile devices, installable Progressive Web Application (PWA) capabilities, and rich offline reading modes.
During Phase 1 version compatibility audits, Next.js 16.x was verified as the current Active LTS release with native Node.js 26 and React 19 support.

## 2. Considered Options

1. **Single Page Application (Vite + React SPA):** Client-side rendering only.
2. **Next.js 15.x:** Previous generation App Router.
3. **Next.js 16.x Active LTS + React 19:** Current LTS App Router with improved Server Components performance, Turbopack default bundling, and enhanced streaming.

## 3. Decision Outcome

Chosen Option: **Option 3 — Next.js 16.x Active LTS + React 19**.

### Justification:

- **Server Components (RSC) by Default:** Public canonical pages (Bible chapters, Synaxarium of the day, Church history) render directly on the server without sending large JavaScript hydration bundles to the client.
- **Turbopack Build Performance:** Sub-second incremental builds across complex multi-route monorepos.
- **Streaming & Suspense:** Enables progressive loading of parallel content (e.g., streaming Bible commentary and cross-references while the chapter text renders immediately).
- **Internationalization & RTL:** Native support for root layout direction (`<html dir="rtl" lang="ar">`) and font optimization (`next/font`).
- **PWA Synergy:** Integrates with Workbox-based service workers for offline caching and manifest delivery.

## 4. Consequences

- **Positive:** Sub-second FCP on mobile networks, superior SEO for Arabic search queries, lightweight client bundles, Turbopack development velocity.
- **Negative:** Strict discipline required to separate Client Components (`'use client'`) from Server Components.
