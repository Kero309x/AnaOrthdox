## 1. Context & Problem Statement

Ana Orthodox requires a production-grade, accessible, and authentic **Material Design 3 (M3)** component system for its Next.js 16 App Router web application. The frontend operates with:

- React 19 (Server Components + Client Components)
- Strict Arabic-first Right-to-Left (RTL) layout requirements
- Zero tolerance for hydration mismatches or unstyled flashes (FOUC)
- Fast mobile performance and small client bundle size
- Requirement for complete state representation (Initial, Loading, Loaded, Empty, No Results, Error, Offline, Partial Data, Refreshing, Disabled)
- Skeleton and shimmer loading system respecting `prefers-reduced-motion`

We must evaluate available React-compatible component solutions and select a coherent, long-term maintainable architecture without introducing competing or conflicting styling frameworks.

## 3. Decision

We choose **Option D**: Build and maintain the complete Material 3 component library in the internal `@ana-orthodox/ui` package, consuming semantic tokens from `@ana-orthodox/design-tokens`, with Tailwind CSS v4 utility classes and semantic CSS custom properties.

### Key Tenets of the M3 Component Architecture:

1. **Strict Token Grounding:**
   Components consume semantic tokens (`--md-sys-color-primary`, `--md-sys-color-surface-container`, `--md-sys-elevation-*`, `--md-sys-shape-*`) rather than arbitrary Tailwind hex colors.
2. **State Layer & Focus Management:**
   All interactive components implement standard M3 state layers (Hover: 8% opacity, Focus: 12% opacity, Pressed: 12% opacity, Dragged: 16% opacity) with accessible `focus-visible` dual-ring indicators meeting WCAG 2.2 AA.
3. **Compound & Composable Architecture:**
   Components follow `vercel-composition-patterns` and `building-components` guidelines: compound components with shared context, slots for flexible layouts, and avoidance of boolean prop proliferation.
4. **Complete 10-State Coverage:**
   Data-driven components explicitly implement and render all 10 states: Initial, Loading, Loaded, Empty, No Search Results, Error, Offline, Partial Data, Refreshing, and Disabled.
5. **Standardized Skeleton & Shimmer System:**
   Every major layout primitive provides a matching `Skeleton` counterpart (`SkeletonText`, `SkeletonAvatar`, `SkeletonCard`, `SkeletonList`, `SkeletonCalendar`, `SkeletonPage`) that mimics content layout to prevent Cumulative Layout Shift (CLS) and supports `prefers-reduced-motion`.

## 4. Consequences & Verification

- **Positive:**
  - Zero external UI library churn or breaking updates.
  - Complete compliance with Next.js 16 App Router Server Components and React 19.
  - 100% testable, zero runtime bundle overhead.
  - Pixel-perfect alignment with approved visual identity and Arabic typography (`Noto Naskh Arabic`).
- **Negative:**
  - Component primitives (Buttons, Cards, Dialogs, Selects, Menus, Navigation, Tabs, Chips, Lists, Snackbars, Progress, Skeletons) must be maintained and tested directly within `@ana-orthodox/ui`.
- **Mitigation:**
  - Rigorous unit testing and a dedicated development component showcase (`/design-system`) demonstrating every variant and state across viewports.
