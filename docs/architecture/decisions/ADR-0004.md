# ADR-0004: PostgreSQL 18.x and Prisma ORM 7.x Stable for Persistence Layer

**Status:** SUPERSEDED & UPDATED (from PostgreSQL 16 baseline to PostgreSQL 18.x + Prisma 7.x Stable)  
**Date:** 2026-11-17  
**Deciders:** Principal Software Architect, Database Agent

---

## 1. Context and Problem Statement

The platform requires strong relational consistency, complex hierarchical queries (Old/New Testament Books -> Chapters -> Verses -> Words -> Cross References), full-text search across sacred texts, and strict schema versioning.
During Phase 1 version compatibility audits, PostgreSQL 18.x was selected as the modern engine target, with Prisma ORM 7.x identified as the stable production ORM release. Prisma ORM 8 release candidates are explicitly excluded per stability requirements.

## 2. Considered Options

1. **MongoDB / Document Store:** Flexible document storage, weak multi-collection relational guarantees.
2. **PostgreSQL with TypeORM:** Relational SQL with Active Record/Data Mapper; historical decorator instability and migration issues.
3. **PostgreSQL 18.x with Prisma ORM 7.x Stable:** Schema-first declarative modeling, auto-generated TypeScript type safety, robust migration engine (`prisma migrate`).

## 3. Decision Outcome

Chosen Option: **Option 3 — PostgreSQL 18.x with Prisma ORM 7.x Stable (7.10.x)**.

### Justification:

- **Declarative Schema as Single Source of Truth:** `schema.prisma` acts as the unambiguous central contract for all entities across the monorepo.
- **End-to-End Type Safety:** Type contracts generated directly from the database schema prevent runtime mismatches between database records and NestJS DTOs.
- **PostgreSQL 18.x Enhancements:** Enhanced GIN indexing for Arabic full-text search, optimized JSONB query performance, and robust connection pooling efficiency.
- **Prisma 7.x Stability:** Major version 7 is locked for stability; Prisma 8 pre-releases are avoided to ensure zero breaking changes in production migrations.
- **Safe Migrations:** `prisma migrate dev` in development and `prisma migrate deploy` in production ensure deterministic schema evolution with zero manual drift.

## 4. Consequences

- **Positive:** Bulletproof referential integrity, complete developer type safety, zero raw SQL injection vectors by default.
- **Negative:** Highly complex dynamic aggregate queries require Prisma raw queries (`prisma.$queryRaw`) with explicit parameterization.
